## 7. 영속성과 재시작 안전성

최종 데이터 소유권은 다음과 같습니다.

- PostgreSQL 18: market/company/execution/notification 정형 상태와 MinIO artifact/pointer metadata
- MinIO: JSON projection, SEC/IR PDF·HTML 원문, immutable seed/source/history
- `macrosquare-spring-data`와 `server/data`: 최초 1회 멱등 import용 read-only 입력

Flyway V1은 운영 PostgreSQL 18.4에서 적용됐고 재기동 시 `schema is up to date`를 확인했습니다. MinIO bucket은 private/versioning enabled이며 애플리케이션은 root 계정이 아닌 전용 최소권한 계정을 사용합니다. mutable object는 MinIO version을 먼저 기록한 후 PostgreSQL active pointer를 ACID transaction으로 교체하고 SHA-256을 검증합니다.

운영 점검 결과 active pointer 12개에 dangling reference가 없었고, 12개가 가리키는 exact MinIO version 본문도 전부 내려받아 PostgreSQL의 SHA-256과 일치함을 확인했습니다. object artifact의 과거 version metadata도 유지됩니다. 백업은 backend 단일 writer를 잠시 정지한 뒤 PostgreSQL custom dump와 각 active pointer가 가리키는 정확한 MinIO version을 함께 보존합니다.

notification state는 candidate 상세까지 원자적으로 저장합니다. 최종 startup source에는 8개 기업 후보가 보존됐고 startup Telegram 전송 로그를 확인했습니다.

```text
Spring startup Telegram notification delivered
```

운영 scheduler는 프로세스 내부 non-overlap guard와 PostgreSQL session advisory lock을 함께 사용합니다.
배포 검증에서 두 DB session으로 동일 disposable key를 경쟁시켜 두 번째 session의 fail-fast와 첫 session
종료 후 재획득을 확인했습니다. 검증 종료 후 granted advisory lock은 0개였습니다. 투자계획 partial PATCH는
transaction advisory lock과 singleton row lock 안에서 읽기·변경·version 증가를 수행하며, 배포 과정은
운영 계획 row를 수정하지 않아 기존 `version=1`, `updated_at`가 그대로 유지됐습니다.
